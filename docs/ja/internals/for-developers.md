# 改造する人へ

スクリプトで自動化したり、アドオンを改造したりするときの地図です。ソースは GPL-3.0-or-later です（`solver/newton_patch/` などの一部は Apache-2.0。各フォルダの `LICENSE` を見てください）。

## 3 つの層

| 層 | 場所 | Blender（bpy）を使うか | 役目 |
|---|---|---|---|
| 型紙の計算 | `core/` | 使わない | 型紙のデータ（JSON の辞書）を読んで直す。作図、縫い目、生地、縫う順番など。Blender なしで試験できる |
| Blender の画面 | アドオン直下の `.py` | 使う | オブジェクトを作る、ツール・パネル・オーバーレイ、選択 |
| 布の計算 | `solver/` | 使わない | 別のプロセスで動く。NVIDIA Newton で布を動かし、結果をファイルで返す |

## 主なモジュール

| モジュール | 中身 |
|---|---|
| `store.py` | 型紙のデータ（テキスト `AC9_ClothSim_Spec_<服>`）を読み書きする唯一の入口 |
| `core/spec.py` | 型紙のデータの形と、それを直す関数。ピースの状態の名前の表 `STATE_NAMES` もここ |
| `core/draft.py` | 作図の編集（角・辺を動かす、ピースを描く、鏡のコピー）。縫い目が壊れないように直す |
| `pattern_view.py` | 平らな型紙のオブジェクトを作る |
| `placed_view.py` | 配置中のピースのオブジェクトを作る。左右の対のミラー、原点、手で動かした分の読み取り |
| `dress.py` | 着せる処理。網目を作り、計算のプロセスを起動し、結果を着た服に戻す |
| `selection.py` | ピースの選択を読み書きする場所（「[選択とギズモ](selection.md)」） |
| `piece_move.py` | 着た服のピースの持ち手 |
| `toolbar.py`・`draft_tool.py` | 左のツールの列のツール |
| `i18n_ja.py` | 画面の日本語 |

## 守っている約束

- **型紙のデータが正。** 平らな型紙のオブジェクトを直接書き換えず、`core/` の関数で型紙のデータを直してから `store.py` で書き戻します。オブジェクトは作り直されます。
- **配置中のピースのオブジェクトは直接動かしてよい。** シミュレーションはそのとき画面にある調整した形から始まります。
- **選択は `selection.py` を通して書く。** 別の場所で `select_set` を呼ぶと、2D と 3D の選択の印がずれます。理由があって直接書いている所は、`tests/test_selection_writers.py` に理由と一緒に並べてあります。
- **画面に出る名前は 1 つの表から読む。** 同じ文字列を 2 か所に書きません（例: ピースの状態は `core/spec.py` の `STATE_NAMES`）。名前を変えたら、試験と説明書も同じ変更で直します。
- **.blend に残る名前**（オブジェクト名・プロパティ名・JSON のキー）を変えるときは、古いファイルが開けることを確かめます。

## 試験

`tests/` の試験は、Blender をバックグラウンドで起動して回します。

```
blender -b --factory-startup --python tests/test_<名前>.py -- <ac9_cloth_sim の親フォルダ>
```
